# 검색 필터·목록·상세 용어 대조

확인일: 2026-09-14. 이번 작업은 조사이며 검색 동작이나 DB는 변경하지 않았다.

## 조사 범위와 근거

- 공식 SCL 검사항목조회 페이지의 실제 검색조건, 분야 11개와 하위 분야 46개, 팀 15개, 질환별 세트 6개를 읽었다.
- 검색조건 B(보험코드), G(검사코드)에 실제 검색어를 넣어 응답을 확인했다. 검색어 파라미터는 `searchKeyword`이다.
- 로컬 SQLite를 읽기 전용으로 열어 공개 활성 검사·검체 조합 3,327건, 상세 데이터 3,326건을 대조했다. 상세 수집 시점은 2026-08-25이다. 공식 목록의 현재 총수는 3,326건으로, 전체 데이터가 오늘 기준으로 동일하다는 뜻은 아니다.
- 현재 Python의 코드 추출·정확 조회·요청 필드 매핑 및 분류 수집 코드를 확인했다. 실제 Gemini 호출은 수행하지 않았다.
- 원자료: `tmp/field-label-audit-20260914/results.json`, `live-searches.json`, `category-options.json`, `live-details.json`, `list.html`.

공식 목록: https://www.scllab.co.kr/front/check/check_item_list.do

## 우선순위 높은 실제 누락

### 1. 보험코드를 급여코드 하나로 좁힌 구현

공식 사이트에서 `searchCnd=B&searchKeyword=CZ135`로 검색하면 small dense LDL cholesterol 정량검사 2건(Serum, Plasma(EDTA))이 반환된다. 목록의 급여/비급여 코드 칸은 두 건 모두 `-`이지만 상세에는 비급여코드 `CZ135`가 있다.

- 직접 검색: https://www.scllab.co.kr/front/check/check_item_list.do?searchCnd=B&searchKeyword=CZ135
- 상세 예시: https://www.scllab.co.kr/front/check/check_item_detail.do?itemcode=10525&sampcode=100
- 로컬 상세에 비급여코드가 있는 조합은 55건이며, 55건 모두 목록에서 가져온 billing_code_text는 `-`이다.
- 현재 프롬프트는 보험코드와 급여코드를 같은 billing 필드라고 지시한다.
- 현재 정확 조회는 목록 billing_code_text와 상세 급여코드만 읽는다. 상세 비급여코드는 빠져 있다.
- 답변 필드 billing도 상세 급여코드만 출력한다.
- 라벨 판별 정규식의 `급여`는 `비급여코드` 안에서도 일치한다. 코드 형식만 확장해도 비급여 구분이 자동으로 해결되지는 않는다.

필요한 구조는 보험코드(통합 검색) 아래 급여코드·비급여코드를 별도로 두는 것이다. 결과에도 코드 종류를 표시해야 한다.

### 2. 테스트 표본 밖의 코드 형식

현재 추출기는 숫자 5자리 또는 영문 1자+숫자 6자리+영문 2자만 인식한다.

| 예시 | 실제 역할 | 공식 검색 확인 | 현재 추출 |
|---|---|---|---|
| D517205KZ | 급여코드 | 1건 | 인식 |
| D4231007Z | 급여코드 | 3건 | 누락 |
| CZ135 | 비급여코드 | 2건 | 누락 |
| R0329 | SCL 검사코드 | 1건 | 누락 |
| 8A088 | 로컬 SCL 검사코드 | 로컬 자료에서 확인 | 누락 |

로컬 고유 SCL 검사코드 2,596개 중 682개가 현재 패턴에 맞지 않는다. 검체 조합으로는 3,327건 중 767건이다. **이는 코드 추출 단계의 누락 수이며 최종 챗봇 오답률을 실측한 수치가 아니다.**

급여 필드에는 `etc`, `etc001`, `etc002`처럼 주석이 붙은 값도 있어 실제 코드와 주석의 분리 정책이 필요하다. 임의의 영숫자 문자열을 모두 코드로 간주하는 방식도 검사명·약어를 오인할 수 있으므로, DB에 저장된 식별자 집합과 질문 라벨을 함께 사용해야 한다.

지난 61개 × 6개 표현 평가 표본은 당시 정규식에 맞는 급여코드에서 추출됐다. 따라서 366/366은 그 표본의 문장 변형과 정확 조회를 검증한 것이며, 전체 코드 형식을 검증한 결과가 아니다.

### 3. 분야·팀·세트 분류가 현재 DB와 맞지 않음

- 공식 분야는 상위 11개·하위 46개다. 현재 taxonomy에는 laboratory_team과 disease_group만 있으며 공식 분야 계층이 저장돼 있지 않다.
- 하위 분야 `결핵검사`는 임상미생물검사 아래 C53과 미생물 분자병리검사 아래 C66에 각각 존재한다. 이름만 키로 사용하면 서로 다른 분류를 합칠 수 있다.
- 공식 필터의 팀은 15개지만 현재 저장한 팀은 소개 페이지에서 읽은 13개다. 출처와 분류 목적이 다르므로 개수 차이만으로 두 팀이 누락됐다고 계산할 수 없다.
- 예: 필터의 `세포유전학팀` ↔ 저장된 `세포유전`, `세포병리학팀` ↔ `세포병리`, `조직병리학팀` ↔ `조직병리`는 명칭 대응 후보다. 같은 조직인지의 확정 매핑은 공식 필터 ID와 연결 관계로 검증해야 한다.
- 필터에는 `자동화운영(화학)팀`과 `자동화운영(면역)팀`이 따로 있다. 저장된 `자동화 운영`으로 모두 합치면 구분을 잃는다.
- 공식 질환별 세트는 포괄적대사검사·갑상선선별검사·간기능검사·지질검사·혈액종합세트검사·산부인과세트검사 6개다.
- 현재 자체 질환 분류 7개는 curated_rule_v1 규칙으로 만든 것이며 공식 세트가 아니다. 검사 연결 377개는 verified=false다.
- 공식 갑상선선별검사(S2)는 현재 7개 항목을 반환한다. 자체 '갑상선 질환'에는 15개 검사 연결이 있다. 둘을 같은 검색 조건으로 취급하면 결과 범위가 달라진다. 검체별 목록과 검사 단위 연결은 집계 단위도 다르다.

세트 예시: https://www.scllab.co.kr/front/check/check_item_list.do?searchOp2=S2&pageUnit=50

### 4. 명칭뿐 아니라 값도 다른 경우

목록과 상세를 공백·대소문자 정규화 후 비교했다. 검사명·SCL 검사코드·검체명은 상세 값이 있는 행에서 불일치가 없었다. 검사방법은 12건의 표기 차이가 있으며 예를 들면 `Real time RT-PCR` ↔ `Real-time RT-PCR`이다.

검사요일 430건, 검사소요일 440건은 목록과 상세가 다르다. 이 차이는 전부 상세의 `/주간`, `/야간`, `-일` 같은 불완전 값에서 발생했다. 두 구체적인 정상 값이 충돌한 것으로 해석하면 안 된다.

예: Secretory IgA (Bronchial), 30220:608은 로컬 목록에서 30일·월~금/주간이지만 상세에는 `-일`·`/주간`이다. 공식 상세를 실시간으로 확인해도 불완전 값이 나타난다. 로컬 목록이 과거 수집값일 수 있으므로 오늘의 소요일로 확정하지 않는다.

단순 동의어 처리와 별도로, 출처·수집 시점·유효값 여부에 따라 표시하는 정책이 필요하다.

## 제안하는 후속 수정 순서

1. 보험코드 통합 검색과 급여/비급여 구분, 전체 실제 코드 형식에 대한 식별자 추출·조회 평가.
2. 화면명·공식 상세 필드·내부 필드·사용자 표현을 연결한 매핑 사전. 소요량·분류번호·급여기준처럼 현재 빠진 요청 필드도 포함.
3. 공식 분야·팀·세트 ID와 검사 연결을 수집하고, 자체 큐레이션 분류와 구분.
4. 불완전 상세값을 유효한 정보로 취급하지 않도록 목록·상세 출처 충돌 처리.

자동 평가에는 알려진 급여코드만이 아니라 비급여코드·영숫자 SCL 코드·필드 별칭·복수 분류·없는 값·불완전 값도 포함해야 한다.
