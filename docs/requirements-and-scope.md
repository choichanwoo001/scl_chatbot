# 요구사항과 구현 범위

기준일: 2026-08-23

## 1. 목표 사용자와 문제

주 사용자는 SCL 검사·업무 정보를 찾는 의료기관 담당자와 일반 홈페이지 방문자다. 기존 메뉴와
버튼만으로는 정확한 용어를 모를 때 검사, 일정 공문, 의뢰서와 위치 정보를 찾기 어렵다.

목표는 공개 정보에 근거한 자연어 탐색, 후속 질문, 안전한 업무 전환을 하나의 데스크톱 채팅
경험으로 제공하는 것이다.

## 4. 데이터 범위

현재 데이터는 SCL 공개 홈페이지에서 수집한 검사항목, 공지, 자료, 콘텐츠, 위치, 메뉴, 용기,
보존제와 분류 정보다. 공개 데이터가 없는 개발용 빈 DB에서만 `DEMO-` 검사 데이터를 사용한다.

다음 정보는 수집·색인 범위가 아니다.

- 실제 환자 검사결과와 판독 내용
- 사용자 ID·비밀번호·본인확인 값
- 기관 내부 검사 DB와 계약 정보
- 채팅 원문 영구 기록
- 검토되지 않은 FAQ 초안의 Vector Store 업로드

## 5. 명시적 제외 범위

- 실제 의료 판단과 개인 결과 해석
- 기관 Gateway 없는 실제 결과조회
- 관리자 대시보드
- 모바일·태블릿 전용 UI
- 스트리밍 응답
- 운영 로그 수집·알림 플랫폼
- rate limit과 다중 인스턴스 세션 공유
- 자동 스케줄러와 무중단 데이터 전환
- 법무·개인정보·의료기기 적합성 승인

## 6. 완료 기준

제출 범위는 다음 조건을 모두 만족할 때 완료로 판단한다.

1. 대표 검사·문서·위치·안전 시나리오가 출처와 함께 동작한다.
2. OpenAI 출력이 존재하지 않는 DB 참조를 생성하면 서버가 답변을 채택하지 않는다.
3. 키가 없는 자동 테스트는 외부 API 비용을 발생시키지 않는다.
4. 백엔드·프런트 자동 테스트와 공개 검색 평가가 통과한다.
5. 미연결 외부 시스템과 운영 전 필수 작업이 제출 문서에 명시된다.

현재 증거는 [통합 평가 보고서](evaluation-report.md), 운영 전 조건은
[한계와 로드맵](limitations-and-roadmap.md)에 정리한다.
