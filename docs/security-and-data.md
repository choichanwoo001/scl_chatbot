# 보안·개인정보·데이터 처리

기준일: 2026-08-28

## 1. 보안 원칙

1. 공개 정보와 개인 정보를 처리 경로부터 분리한다.
2. LLM 출력과 Vector 검색 결과를 신뢰하지 않고 로컬 RDB로 다시 검증한다.
3. 인증정보는 LLM provider, 브라우저 저장소와 로컬 DB에 보존하지 않는다.
4. 필요한 최소 데이터만 외부 서비스에 전달한다.
5. 운영에 필요한 비밀은 백엔드 환경변수나 Secret Manager에서 주입한다.

## 2. 데이터 분류와 흐름

| 데이터 | 처리·저장 위치 | 외부 AI 전송 | 현재 보존 |
|---|---|---|---|
| SCL 공개 검사·문서 | 로컬 RDB | 검색 후보로 가능 | 동기화 데이터 유지 |
| 공개 문서 Vector 원문 | 로컬 Gemini Index | 인덱스 생성·검색 활성화 시 | 생성된 로컬 인덱스 유지 |
| 일반 사용자 질문 | 백엔드 메모리 세션 | 마스킹 후 전송 | 세션 종료·재시작까지 |
| 안전한 채팅 UI 상태 | 브라우저 `sessionStorage` | 해당 없음 | 탭 세션까지 |
| ID·비밀번호·본인확인 값 | 메모리 → 결과 Gateway | 금지 | 저장하지 않음 |
| 개인 검사결과 | 결과 Gateway 응답 | 금지 | 브라우저 영구 저장 금지 |
| 상담 요청 | 암호화 RDB | 금지 | 정책 미정 |
| 답변 피드백 | PII 마스킹 후 RDB | 금지 | 정책 미정 |
| API 키·인증서·암호화 키 | 서버 Secret | 금지 | 운영 Secret 정책 |

## 3. 외부 AI 전송 경계

Gemini에는 입력 검사 후의 질문, 제한된 대화 이력, 공개
검사·문서 후보가 전달될 수 있다. Gemini 임베딩 인덱스 생성 시에는 공개 문서·첨부 텍스트가
embedding API로 전송된다.
전화번호·주민등록번호 패턴은 모델 호출 전에 마스킹한다. Prompt Injection과 반복·단순 욕설은
모델 계획 단계로 보내지 않고 서버에서 응답한다.

다음 값은 Gemini 전송 대상이 아니다.

- 개인 결과 로그인 ID·비밀번호·본인확인 값
- 실제 개인 검사결과 원문
- 상담 접수 폼의 이름·전화번호·기관명·내용
- 서버 API 키, Gateway client secret, 인증서 개인키
- Fernet 키

## 4. 입력·출력 통제

- 입력 최대 길이 500자
- 전화번호·주민등록번호 마스킹
- Prompt Injection 패턴 차단
- 반복 문자·단순 욕설 차단, 업무 의도가 있는 욕설은 경고 후 처리
- Gemini 기본 안전 필터 적용
- Structured Output의 도메인·하위 의도 조합 검증
- 모델이 제시한 검사 코드·공개 ref를 RDB에서 재조회
- 존재하지 않는 참조와 모델 작성 임의 출처 거부
- SCL HTTPS 도메인만 출처 URL로 허용
- 모델 자유서술은 사실 답변으로 직접 노출하지 않고 서버가 검증된 레코드로 다시 조립
- 내부 근거가 없으면 고정된 답변 보류 문구를 사용하며 모델의 `no_source` 답변은 폐기
- SCL 검사코드·검체·용기·일정·소요일·연락처는 외부 일반 자료로 보완하지 않음

## 5. 인증정보와 개인 결과

개인 결과 Provider는 `unconfigured`, 자동 테스트용 `mock`, 승인된 `http` 모드를 분리한다.
운영 HTTP Provider는 다음을 적용한다.

- 기본 HTTPS 강제, 개발용 HTTP는 명시적 플래그 필요
- redirect 비활성
- 사설 CA와 mTLS 인증서 지원
- client ID·secret 지원
- 인증 만료와 401·403·404·429·5xx 오류 매핑
- 최대 20페이지 pagination 제한
- 제공자 만료시간과 로컬 최대 15분 중 짧은 세션 사용
- 로그아웃·채팅 종료 시 토큰 제거

계약은 [OpenAPI 부록](appendices/technical/result-provider-openapi.yaml)에 정의한다.

## 6. 저장 암호화와 Secret

상담 요청의 이름, 전화번호, 기관명과 내용은 Fernet으로 암호화해 저장한다. 개발 환경에서
`FIELD_ENCRYPTION_KEY`가 없으면 `data/.field-encryption.key`를 생성하지만 운영에서는 이 동작에
의존하지 않고 Secret Manager에서 고정 키를 주입해야 한다.

`.env`, 로컬 암호화 키, 원본 첨부, 가상환경과 빌드 산출물은 Docker context·Git 추적에서
제외한다. `GEMINI_API_KEY`를 `VITE_` 환경변수로 만들면 브라우저 번들에
노출되므로 금지한다.

## 7. Vector 데이터 통제

업로드 가능한 대상은 다음으로 제한한다.

- 본문 또는 요약이 있는 활성 공개문서
- 활성 공개문서에 연결되고 추출 완료된 첨부
- 검토 후 `published` 상태인 FAQ

검사항목 구조화 필드, 채팅 기록, 개인 결과, 상담, 피드백과 FAQ 초안은 색인하지 않는다.
Gemini 로컬 인덱스 결과는 로컬 ref와 공개 원문이 존재해야 답변
근거로 사용할 수 있다.

## 8. 남은 보안 작업

- 운영 rate limit·WAF·IP/계정별 남용 통제
- 중앙 감사 로그와 민감값 비기록 검증
- 상담·피드백 보존기간과 삭제 요청 절차
- 다중 인스턴스 토큰·세션 저장소
- Secret Manager·키 회전 자동화
- SAST·의존성 취약점·컨테이너 이미지 스캔
- 실제 Gateway 침투·계약 테스트
- 법무·개인정보·의료 관련 내부 승인

본 문서는 구현 통제를 설명하며 법률 자문이나 개인정보 영향평가를 대체하지 않는다.
